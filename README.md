# Сканер сетапов: BTC, ETH, SOL (снятие ликвидности → IFVG → вход по ретесту, RR≥1.0)

Бесплатно. Работает на данных Binance Futures (без ключей и регистрации),
гоняется каждые 15 минут в GitHub Actions, присылает алерт в Telegram.

Мониторит: BTC, ETH, SOL — все три отдельно проверены на реальной истории
(6-7 лет для BTC/ETH, 3+ года для SOL), Profit Factor 2.3-3.6, суммарно
~2.2 сигнала в неделю на все три вместе.

Логика скрипта — тот же код, что и в бэктесте. Ничего не торгует сама,
только присылает уровни входа/стопа/тейка — вход ты ставишь руками на
демо-счёте.

## Важно: кластерный риск

Монеты сильно коррелируют между собой. Если сканер пришлёт сигналы сразу
по 3+ активам одновременно — это, скорее всего, ОДНО движение рынка, а
не несколько независимых сигналов. В таком случае сканер сам пришлёт
отдельное предупреждение "⚠️ Кластерный сигнал" — увидишь его, раздели
свой обычный риск на сделку (например 1%) между всеми активами в
кластере (по 0.15-0.3% на каждый), а не бери полный риск на каждый.


## Шаг 1. Создать Telegram-бота (2 минуты)

1. В Telegram найди **@BotFather**, напиши ему `/newbot`.
2. Придумай имя и юзернейм бота (любые, например `oli_btc_scanner_bot`).
3. BotFather пришлёт **токен** вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.
   Сохрани его — это `TELEGRAM_TOKEN`.
4. Напиши своему новому боту в Telegram что угодно (например "привет"),
   чтобы у него появился диалог с тобой.
5. Открой в браузере (подставив свой токен):
   `https://api.telegram.org/bot<ТВОЙ_ТОКЕН>/getUpdates`
   Найди в ответе число `"chat":{"id": 123456789, ...}` — это `TELEGRAM_CHAT_ID`.

## Шаг 2. Завести аккаунт GitHub (если ещё нет)

1. https://github.com/signup — бесплатно.
2. Создай новый репозиторий: кнопка **New repository**, назови как хочешь
   (например `btc-scanner`), сделай **Private** (чтобы твои алерты и код
   не были публичными), нажми **Create repository**.

## Шаг 3. Залить файлы в репозиторий

В интерфейсе GitHub: **Add file → Upload files**, перетащи туда все файлы
из этой папки (`scanner.py`, `requirements.txt`, `state.json`, папку
`.github` целиком) и нажми **Commit changes**.

## Шаг 4. Добавить секреты (токен и chat_id)

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.
Добавь два секрета:
- `TELEGRAM_TOKEN` — значение из шага 1.3
- `TELEGRAM_CHAT_ID` — значение из шага 1.5

## Шаг 5. Включить и проверить

1. Перейди во вкладку **Actions** репозитория — GitHub может спросить
   подтверждение, что workflow'ы разрешены, нажми **I understand, enable**.
2. Слева выбери **BTC setup scanner** → справа **Run workflow** → **Run workflow**
   (это ручной запуск для проверки, не дожидаясь 15 минут).
3. Открой запуск, посмотри лог шага **Run scanner** — если всё ок, увидишь
   строку вида `OK. trend= 1 pending= False position= False`.
4. Дальше скрипт будет запускаться сам каждые 15 минут и писать тебе в
   Telegram при появлении сетапа, исполнении входа и закрытии сделки.

## Что если нужно поменять параметры

Все настройки — в начале `scanner.py` (SYMBOL, MIN_RR, MAX_SWEEP_DEPTH_ATR
и т.д.) — те же имена и значения, что мы использовали в проверенном
бэктесте. Поменяла — закоммитила — с следующего запуска работает по-новому.

## Ограничения, которые нужно понимать

- Бесплатный GitHub Actions даёт ~2000 минут в месяц на приватный
  репозиторий — этого более чем достаточно (скрипт выполняется секунды,
  запусков ~2880/мес).
- Cron в GitHub Actions не гарантирует точность до минуты — иногда
  срабатывает с задержкой в несколько минут при высокой нагрузке на
  сервисы GitHub. Для 15-минутного таймфрейма это не критично.
- Скрипт пересчитывает всё заново на последних ~200 днях данных при
  каждом запуске (не хранит историю сам) — это сделано специально,
  чтобы не было расхождений между тем, что проверялось на бэктесте, и
  тем, что реально гоняется вживую.
